\section{Two-Player Game Search}

\subsection*{Minimax}
MAX (us) maximises, MIN (opponent) minimises; players alternate.\\
Back up values from terminals: MAX node = \(\max\) of children; MIN node = \(\min\) of children.\\
Optimal vs an optimal opponent; minimises the maximum loss the opponent can force.\\
Real games: cut off at depth, use evaluation \(e(p)\) (e.g. \( e=\#\text{open}(X)-\#\text{open}(O) \)); horizon effect.\\
DFS-based: Time \( O(b^m) \), Space \( O(m) \). TTT \(b\!\approx\!5,d\!=\!9\); checkers \(b\!\approx\!35\).

\subsection*{Alpha-Beta Pruning}
\( \alpha \)= best (max) value MAX can guarantee so far; \( \beta \)= best (min) value MIN can guarantee.\\
Prune subtree when \( \alpha\ge\beta \) (cannot affect the result).\\
Same value as minimax; move ordering is decisive.\\
Worst case \( O(b^d) \); perfect ordering \( O(b^{d/2}) \), so effective branching \( \approx\sqrt{b} \) \(\Rightarrow\) doubles reachable depth for same cost.

\subsection*{Alpha-Beta on Tree Above}
Left MIN returns 3 \(\Rightarrow \alpha=3\) at the root.\\
Right MIN examines its first child 2 \(\Rightarrow \beta=2\); since \(\alpha=3\ge\beta=2\), prune its remaining children (the 4 and 6 are never examined).\\
Lesson: order best moves first to maximise pruning.
